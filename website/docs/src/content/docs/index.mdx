**Git tells you what code changed. Nothing tells the next developer what that change means for them.**

Agents Handoff closes that gap. Your coding agent writes a short, structured `HANDOFF.md`
about a change you just finished. Your teammate’s agent reads it in *their* repository and
knows exactly what to change — and what not to build.

```
finish a change
  → "write a handoff for the mobile team"
  → .handoff/<id>/HANDOFF.md, which you review
  → export the complete Markdown file
  → their agent reads it, checks its own code, and plans the work
```

## How it thinks

- **The tool collects the facts, the agent does the reasoning.** Routes, auth guards, types,
  migrations and environment variables are gathered from git deterministically. The core
  never calls a model. What the change *means* to another team is written by the agent that
  built it with you.
- **Local files.** Writing, validating, exporting and receiving a handoff happen on your
  machine. The exported Markdown contains the complete handoff for people and agents.
- **You decide.** Review the Required Actions, export the document, and give the file to the
  other team. The receiving agent checks its own code and implements only when asked.

## Export the handoff

After reviewing a handoff, export its complete Markdown:

```sh
handoff export <file|id> --out ./HANDOFF.md
```

Without `--out`, the file is written to `.handoff/exports/<id>.md`. An MCP client can use
`handoff_export` for the same operation. The result reports the exported file path and its
source path. The other team can read the file directly or ask its agent to receive it.
