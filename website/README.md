# Website

Two static sites, both built with [Astro](https://astro.build) (MIT):

| Site | Directory | Built with | Served from |
|---|---|---|---|
| Landing page | `landing/` | Astro | `https://<domain>` |
| Documentation | `docs/` | Astro + [Starlight](https://starlight.astro.build) | `https://docs.<domain>` |

Both are plain HTML, CSS and a little JavaScript once built — no server, no analytics, no
third-party fonts or scripts. Search in the docs is [Pagefind](https://pagefind.app), built
into the site at build time, so it needs no search service either.

## The docs are generated, not written twice

Every docs page except the introduction (`docs/src/content/docs/index.mdx`) is generated by
`docs/scripts/sync-docs.mjs` from the Markdown this repository already has: the README's
sections, `SPEC.md`, `docs/*.md`, `SECURITY.md`, `CHANGELOG.md`, `CONTRIBUTING.md` and the
Codex plugin's README. Links between those files become links between pages, and links to
anything else become links to the file on GitHub.

So **edit the source file, not the generated page** — the generated pages are gitignored,
and each one's "Edit page" link points at its source. To add a page, add an entry to
`PAGES` in the script and a sidebar item in `docs/astro.config.mjs`.

## Running it

Requires Node.js 22.12 or later.

```bash
cd website
npm install
npm run dev:landing      # http://localhost:4321
npm run dev:docs         # http://localhost:4322 (regenerates the pages first)
npm run build            # both, into landing/dist and docs/dist
```

Search only works in a build: `npm run build && npm run preview:docs`.

## Deploying, and the docs subdomain

The two sites are two projects on any static host that builds from a git repository —
Cloudflare Pages, Vercel and Netlify all do this for free. Create both from this
repository with these settings:

| Setting | Landing project | Docs project |
|---|---|---|
| Root directory | `website` | `website` |
| Install command | `npm ci` | `npm ci` |
| Build command | `npm run build --workspace landing` | `npm run build --workspace docs` |
| Output directory | `landing/dist` | `docs/dist` |
| Environment variable | `SITE_DOMAIN=<domain>` | `SITE_DOMAIN=<domain>` |
| Custom domain | `<domain>` | `docs.<domain>` |
| Node.js version | 22 or later | 22 or later |

`SITE_DOMAIN` is the one setting that matters: it is read by `site.config.mjs`, so every
link from one site to the other, every canonical URL and the docs sitemap point at the real
domain. Without it, the links point at `localhost`.

The subdomain itself is a DNS record at your domain registrar: add the custom domain
`docs.<domain>` to the docs project, and the host tells you the `CNAME` record to create.
The landing page gets the apex domain the same way.

GitHub Pages is not a good fit here: it serves one custom domain per repository, and this
setup needs two.
